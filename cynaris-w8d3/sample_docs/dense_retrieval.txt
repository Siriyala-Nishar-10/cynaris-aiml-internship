Dense retrieval represents text as vectors produced by an embedding model. A question and every passage are turned into lists of numbers, and passages whose vectors point in a similar direction, measured with cosine similarity, are returned as matches. Because the vectors capture meaning, dense retrieval can match a question to a passage that uses different words, for example linking car with automobile. The cost is that an embedding model must run for every document at indexing time and for every query, which needs more memory and compute than keyword search, and the quality depends on how well the embedding model fits the subject area. Dense retrieval can miss exact identifiers or numbers that keyword search finds easily.
